# 支出登録画面 詳細設計

## 1. 目的

ユーザーが日々の支出を、少ない操作で簡単に登録できる画面を設計する。

最優先事項は、金額入力から登録完了までの操作負担を小さくすることである。

## 2. 画面情報

| 項目 | 内容 |
|---|---|
| 画面名 | 支出登録 |
| パス | `/expenses/new` |
| 認証 | 必須 |
| 必須項目 | 金額、カテゴリ、日付 |
| 任意項目 | メモ |
| 登録先 | 支出データ |

## 3. 画面レイアウト

```text
┌──────────────────────────────┐
│ 支出を登録                     │
├──────────────────────────────┤
│ 金額                           │
│       ¥ 1,200                 │
├──────────────────────────────┤
│ カテゴリ                       │
│ [食費] [日用品] [交通費]        │
│ [趣味] [交際費] [その他]        │
├──────────────────────────────┤
│ 日付                           │
│ [2026/10/15              📅]   │
├──────────────────────────────┤
│ メモ（任意）                   │
│ [例：昼食                   ]  │
├──────────────────────────────┤
│         [支出を登録]            │
└──────────────────────────────┘
```

※レイアウトは設計イメージ。実際のカテゴリはDBから取得する。

## 4. 入力項目

| 項目 | 型 | 必須 | 初期値 | 制約 |
|---|---|---|---|---|
| 金額 | 整数 | 必須 | 空欄 | 1以上の整数 |
| カテゴリ | カテゴリID | 必須 | 未選択 | 支出用カテゴリから選択 |
| 日付 | 日付 | 必須 | 今日 | 有効な日付 |
| メモ | 文字列 | 任意 | 空欄 | 最大500文字を目安とする |

金額は表示時に通貨形式に整形してもよいが、保存時には数値として扱う。小数を許可しない日本円の家計簿として設計する。

## 5. 操作フロー

1. 金額を入力する
2. カテゴリを選択する
3. 必要に応じて日付を変更する
4. 必要に応じてメモを入力する
5. 「支出を登録」を押す
6. サーバー側で認証・入力値を検証する
7. 登録成功後、支出一覧またはダッシュボードへ遷移する

## 6. バリデーション

| 項目 | 条件 | エラーメッセージ例 |
|---|---|---|
| 金額 | 未入力 | 金額を入力してください |
| 金額 | 0以下 | 金額は1円以上で入力してください |
| 金額 | 整数以外 | 金額は整数で入力してください |
| 金額 | 数値として不正 | 正しい金額を入力してください |
| カテゴリ | 未選択 | カテゴリを選択してください |
| カテゴリ | 支出用でない・他人のもの | 選択したカテゴリを利用できません |
| 日付 | 未入力・不正 | 正しい日付を入力してください |
| メモ | 最大文字数超過 | メモは500文字以内で入力してください |

クライアント側で入力しやすさを確保し、サーバー側でも同じルールを検証する。

## 7. UIの振る舞い

### 金額入力

- 画面内で最も目立つ位置に配置する
- 数字を入力しやすいUIにする
- 不正な文字列をそのまま送信しない
- 入力値と表示用フォーマットを適切に分離する

### カテゴリ選択

- ボタンまたはカード形式で表示する
- 選択中のカテゴリを視覚的に区別する
- 支出用カテゴリのみ表示する
- カテゴリが存在しない場合は、カテゴリ追加画面への導線を表示する

### 日付入力

- 初期値は今日
- ユーザーが過去の日付を指定できる
- 日付のタイムゾーンや保存形式を統一する

### メモ入力

- 任意項目と明示する
- 入力しなくても登録できる
- 長文になりすぎないよう文字数制限を設ける

## 8. 登録ボタンの状態

| 状態 | 振る舞い |
|---|---|
| 入力中 | 通常表示 |
| バリデーションエラー | 対象項目にエラー表示 |
| 送信中 | ボタンを無効化し、処理中と表示 |
| 成功 | 成功通知後に一覧へ遷移 |
| 失敗 | 入力値を維持してエラー表示 |

送信中は二重送信を防止する。ただし、クライアント側のボタン無効化だけを唯一の対策としない。

## 9. API連携

登録先のAPIは `POST /api/expenses` とする。

リクエスト例：

```json
{
  "amount": 1200,
  "categoryId": "category-uuid",
  "date": "2026-10-15",
  "memo": "昼食"
}
```

- `userId` はリクエスト本文から受け取らない
- ユーザーIDはサーバー側の認証情報から取得する
- `categoryId` がログインユーザーの支出カテゴリであることを検証する
- 入力値の検証に失敗した場合は、共通エラー形式で返す

## 10. コンポーネント設計

初期実装では、画面全体の責務を持つフォームコンポーネントを中心にする。

```text
ExpenseForm
├── AmountInput
├── CategorySelector
├── DateInput
├── MemoInput
└── SubmitButton
```

項目コンポーネントは、再利用性や複雑さが必要になった段階で分割する。小さなコンポーネントを最初から大量に作ることは避ける。

## 11. テスト観点

- 金額・カテゴリ・日付が正しい場合に登録できる
- メモを空欄にして登録できる
- 金額が0以下の場合は登録できない
- カテゴリ未選択の場合は登録できない
- 不正なカテゴリIDを受け付けない
- 他ユーザーのカテゴリを利用できない
- APIエラー時に入力値が保持される
- 送信中に二重送信できない
- 登録後、一覧やダッシュボードに反映される
